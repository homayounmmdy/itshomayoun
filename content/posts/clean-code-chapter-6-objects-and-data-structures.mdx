# اشیاء و ساختارهای داده؛ دو روی یک سکه

فصل ششم کتاب **Clean Code** به یکی از مهم‌ترین تمایزها در طراحی نرم‌افزار می‌پردازد: تفاوت بین **اشیاء (Objects)** و **ساختارهای داده (Data Structures)**. درک این تفاوت و پرهیز از ترکیب آن‌ها، کلید نوشتن کدی است که در برابر تغییرات آینده مقاوم باشد.

در ادامه، اصول کلیدی این فصل را مرور می‌کنیم.

## ۱. انتزاع داده (Data Abstraction)
پنهان کردن پیاده‌سازی فقط به معنای اضافه کردن `getter` و `setter` به متغیرهای خصوصی نیست! انتزاع داده یعنی ارائه یک **رابط (Interface) انتزاعی** که به کاربر اجازه می‌دهد بدون دانستن ساختار زیرین، با داده کار کند.
> 💡 **مثال:** متد `getPercentFuelRemaining()` (درصد سوخت باقی‌مانده) بسیار بهتر از `getGallonsOfGasoline()` (گالن بنزین) است، زیرا جزئیات پیاده‌سازی (گالن، لیتر یا درصد) را پنهان می‌کند.

## ۲. تقارن معکوس: شیء در مقابل ساختار داده
این دو مفهوم دقیقاً برعکس یکدیگر عمل می‌کنند:
* **اشیاء (Objects):** داده را **پنهان** می‌کنند و رفتار (Behavior) را **آشکار** می‌کنند. 
  - *مزیت:* افزودن **انواع جدید** (کلاس‌های جدید) آسان است.
  - *عیب:* افزودن **توابع جدید** سخت است (باید همه کلاس‌ها را تغییر دهید).
* **ساختارهای داده (Data Structures):** داده را **آشکار** می‌کنند و رفتار معناداری **ندارند**.
  - *مزیت:* افزودن **توابع جدید** آسان است.
  - *عیب:* افزودن **انواع جدید** سخت است (باید همه توابعی که این ساختار را می‌گیرند تغییر دهید).

> ⚖️ **قانون طلایی:** اگر نیاز دارید مدام **انواع داده جدید** اضافه کنید، از «اشیاء» استفاده کنید. اگر نیاز دارید مدام **عملیات (توابع) جدید** اضافه کنید، از «ساختارهای داده» استفاده کنید.

## ۳. قانون دمیتر (Law of Demeter)
> **«فقط با دوستان صحبت کن، نه با غریبه‌ها.»**

یک متد فقط باید متدهای موارد زیر را فراخوانی کند:
1. خودش
2. اشیایی که خودش می‌سازد
3. اشیایی که به عنوان آرگومان دریافت می‌کند
4. متغیرهای نمونه (Instance variables) خودش

* **قطارهای تصادف (Train Wrecks):** از زنجیره‌کردن فراخوانی‌ها به‌شدت پرهیز کنید (مثل `ctxt.getOptions().getScratchDir().getAbsolutePath()`). این کار وابستگی‌های عمیق و شکننده ایجاد می‌کند.
* **راه‌حل:** به شیء بگویید کار را انجام دهد، نه اینکه داده‌هایش را از شما بگیرد (مثل `ctxt.createScratchFileStream()`).

## ۴. دوری از هیبریدها و استفاده صحیح از DTOها
* **هیبریدها (Hybrids):** ترکیب اشیاء و ساختارهای داده (متغیرهای عمومی + رفتارهای پیچیده تجاری) **بدترین حالت ممکن** است. مزایای هر دو را از دست می‌دهید و معایب هر دو را به ارث می‌برید.
* **DTOها (Data Transfer Objects):** ساختارهای داده **خالص** با متغیرهای عمومی (یا getter/setter ساده) و **بدون هیچ رفتاری**. این‌ها برای ارتباط با دیتابیس یا شبکه عالی هستند.
* **Active Records:** همان DTOها به همراه متدهای ناوبری ساده مثل `save()` یا `find()`. **هشدار:** منطق تجاری (Business Logic) نباید در آن‌ها باشد؛ آن را در اشیاء جداگانه‌ای نگه دارید که از Active Record به‌عنوان داده استفاده می‌کنند.

## مثال‌های کد (JavaScript)

```javascript
// ❌ بد: افشای پیاده‌سازی، نقض قانون دمیتر، و طراحی هیبریدی
class Vehicle {
  // افشای ساختار داده داخلی
  getGallonsOfGasoline() { return this.gallons; } 
  getTankCapacity() { return this.capacity; }
}

// نقض قانون دمیتر (Train Wreck)
const path = context.getOptions().getScratchDir().getAbsolutePath();

class User {
  // هیبریدی: هم دسترسی عمومی به داده دارد و هم رفتار تجاری پیچیده
  publicData = {}; 
  processComplexPayment() { /* ... */ } 
}


// ✅ تمیز: انتزاع داده (پنهان‌سازی پیاده‌سازی)
class Vehicle {
  // رفتار انتزاعی را آشکار می‌کند و پنهان می‌کند که داخلی از گالن، لیتر یا درصد استفاده می‌کند
  getPercentFuelRemaining() {
    return (this.gallons / this.capacity) * 100;
  }
}

// ✅ تمیز: قانون دمیتر ("بگو، نپرس" - Tell, don't ask)
// اجازه دهید شیء context مدیریت ناوبری داخلی خودش را بر عهده بگیرد
const outputStream = context.createScratchFileStream("output.txt");


// ✅ تمیز: جداسازی دقیق DTO و شیء (بدون هیبرید)
// ۱. DTO خالص: داده را آشکار می‌کند، بدون رفتار
class UserDTO {
  constructor(id, name) {
    this.id = id;
    this.name = name;
  }
}

// ۲. شیء خالص: داده را پنهان می‌کند، رفتار را آشکار می‌کند
class UserService {
  constructor(userDTO) {
    this.user = userDTO; 
  }
  
  save() {
    // منطق تجاری روی DTO پنهان‌شده اعمال می‌شود
    console.log(`Saving user ${this.user.name}`);
  }
}
```
