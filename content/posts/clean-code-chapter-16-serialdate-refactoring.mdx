# پالایش SerialDate؛ از کد کثیف تا طراحی زیبا

فصل شانزدهم کتاب **Clean Code** یکی از ارزشمندترین بخش‌های این کتاب است؛ یک **مطالعه موردی کاملاً عملی** که در آن رابرت مارتین کلاس واقعی `SerialDate` (از کتابخانه JCommon) را خط به خط ریفکتور می‌کند. این فصل نشان می‌دهد که چگونه می‌توان یک کد شلوغ و قدیمی را به یک طراحی تمیز، گویا و قابل نگهداری تبدیل کرد.

در ادامه، مهم‌ترین درس‌های این فرآیند پالایش را مرور می‌کنیم.

## ۱. گام‌های اولیه پالایش
* **اول کار کن، بعد تمیز کن:** قبل از هرگونه ریفکتورینگ، از پوشش تستی بالا مطمئن شوید. باگ‌های شرایط مرزی (Boundary Conditions) را رفع کنید و رشته‌های خطا را با استثناهای مناسب (مثل `IllegalArgumentException`) جایگزین کنید.
* **نام‌های معنادار:** نام کلاس‌ها و متغیرها را تغییر دهید تا نیت را بازتاب دهند و پیاده‌سازی را پنهان کنند. (مثلاً `SerialDate` به `DayDate` و `suffixIndex` به `suffixLength`).

## ۲. اصول طراحی پیشرفته
* **Enums به جای اعداد جادویی:** ثابت‌های عددی (ماه‌ها، روزها، بازه‌ها) را با Enumهای دارای تایپ قوی (Strongly-typed) جایگزین کنید. این کار ایمنی تایپ را تضمین کرده و متدهای اعتبارسنجی دستی را حذف می‌کند.
* **کارخانه انتزاعی (Abstract Factory):** از یک Factory برای ساخت نمونه‌ها و پاسخ به سوالات خاص پیاده‌سازی (مثل حداقل/حداکثر سال) استفاده کنید تا کلاس پایه انتزاعی تمیز بماند.
* **Push Down / Pull Up:** داده‌های خاص پیاده‌سازی (مثل حدود ترتیبی) را به کلاس‌های مشخص **پایین** ببرید. منطق مستقل از پیاده‌سازی (مثل `compare` یا `daysSince`) را به کلاس پایه انتزاعی **بالا** بیاورید.
* **نمونه به جای استاتیک:** متدهای وابسته به وضعیت (State-dependent) را از استاتیک به متدهای نمونه (Instance) تغییر دهید. آن‌ها را به‌طور واضح نام‌گذاری کنید (مثلاً `plusDays` به جای `addDays`) تا نشان دهید یک شیء **جدید** برمی‌گردانند، نه اینکه شیء فعلی را تغییر دهند.

## ۳. پلی‌مورفیسم و حذف زوائد
* **پلی‌مورفیسم به جای Switch:** دستورهای `switch` را با انتقال منطق شرطی به متدهای پلی‌مورفیک درون خودِ Enumها جایگزین کنید. این کار اصل Open/Closed را رعایت می‌کند.
* **حذف زوائد (Remove Clutter):** کامنت‌های تکراری، تاریخچه تغییرات (به جای آن از **Git** استفاده کنید)، متدهای استفاده‌نشده و کلمات کلیدی غیرضروری مثل `final` را بی‌رحمانه حذف کنید.

## مثال‌های کد (JavaScript)

```javascript
// ❌ قبل از پالایش: اعداد جادویی، متدهای استاتیک مبهم، دستورهای switch، رشته‌های خطا
class DateUtils {
  // نام متد استاتیک "add" به‌طور مبهمی به تغییر شیء فعلی یا برگرداندن شیء جدید اشاره می‌کند
  static addDays(date, days) { 
    return new Date(date.getTime() + days * 86400000);
  }

  static isInRange(date, d1, d2, intervalType) {
    // دستور switch اصل Open/Closed را نقض می‌کند
    switch (intervalType) {
      case 0: return date > d1 && date < d2; // OPEN
      case 1: return date >= d1 && date <= d2; // CLOSED
      default: return "Invalid interval type"; // برگرداندن رشته خطا!
    }
  }
}


// ✅ بعد از پالایش: Enumهای پلی‌مورفیک، نام‌گذاری شفاف نمونه، الگوی Factory

// Enum پلی‌مورفیک با منطق داخلی
const DateInterval = {
  OPEN: (d, left, right) => d > left && d < right,
  CLOSED: (d, left, right) => d >= left && d <= right,
};

class DayDate {
  constructor(ordinal) {
    this.ordinal = ordinal;
  }

  // متد نمونه با پیشوند "plus" به‌وضوح نشان می‌دهد که یک شیء جدید برگردانده می‌شود
  plusDays(days) {
    return DayDateFactory.makeDate(this.ordinal + days);
  }

  isInRange(d1, d2, interval) {
    const left = Math.min(d1.ordinal, d2.ordinal);
    const right = Math.max(d1.ordinal, d2.ordinal);
    
    // پلی‌مورفیسم: تابع interval منطق را مدیریت می‌کند، نیازی به switch نیست
    return interval(this.ordinal, left, right); 
  }
}

// کارخانه انتزاعی جزئیات پیاده‌سازی (مثلاً SpreadsheetDate در برابر DayDate) را پنهان می‌کند
class DayDateFactory {
  static makeDate(ordinal) {
    return new DayDate(ordinal); // پیاده‌سازی مشخص در اینجا پنهان شده است
  }
}
```
